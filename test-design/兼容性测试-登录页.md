## 三、发现的问题

### C-01　`100vh` 在移动端会跳（代码层，建议修）

`.phone{min-height:100vh}`：iOS Safari 与 Chrome Android 的 `100vh` 包含地址栏高度，地址栏收起/展开时页面高度突变，底部版权文字会跟着跳。桌面端不受影响。

**建议**：改用 `min-height:100dvh`（新内核），并保留 `100vh` 作为降级；或加一段 JS 把视口高度写进 CSS 变量。

### C-02　置灰按钮文字对比度不足（视觉，建议修）

`button:disabled{background:#c8e6d0}` 配 `color:#fff`，对比度约 **1.5:1**（WCAG 正文要求 ≥4.5:1）。强光或低亮度屏幕上「下一步」几乎看不清，用户不知道按钮为什么点不动，容易误判为页面卡死。

**建议**：置灰态改成灰字（`#8a8a8a`）+ 浅灰底，或把文字改成「请先输入手机号」这类可读提示。

### C-03　字体栈缺 Android 中文字体（代码层，观察项）

`-apple-system,"Segoe UI","Microsoft YaHei","PingFang SC",sans-serif`：Android 上没有前三个字体，会回退到系统默认（Roboto / Noto Sans CJK）。中文行高与断行位置会和 iOS、Windows 不一致，长文案（协议、错误提示）的换行点可能不同。

**建议**：字体栈补 `"Noto Sans CJK SC","Source Han Sans SC"`，或在 Android 真机上回归一次长文案。

### C-04　短信验证码用 `alert()`（交互，建议修）

`$('sms')` 里直接 `alert('短信验证码登录暂未开放')`。部分 App 内置 WebView 会拦截 alert，用户点了没反应；样式也不可控。

**建议**：改成页内 Toast 或 `.err` 提示。

### C-05　iOS 点击出现灰色高亮（视觉，可选）

未设置 `-webkit-tap-highlight-color`，iOS Safari 点击按钮/链接时会出现一块灰色高亮，与设计稿不符。

**建议**：`-webkit-tap-highlight-color: transparent`，并用 `:active` 自己做按压态。

### C-06　键盘弹起可能遮挡按钮（待真机验证）

密码页 `input:focus` 会拉起软键盘，`.phone` 用 `100vh` 撑高且底部有 `margin-top:auto` 的版权文字。键盘弹起后可视区域变小，登录按钮可能被顶出视口或被遮挡。**本机无法验证，需 iOS/Android 真机确认。**

## 五、复现步骤

1. 用 Edge 打开 `test-design/target/login-demo.html`；
2. F12 → 设备工具栏，依次设 1920×1080、1366×768、375×667，观察是否出现横向滚动条；
3. 375 视口下观察「下一步」置灰态的文字可读性（对应 C-02）；
4. 查看源码 `.phone` 的 `min-height`（对应 C-01）、`body` 的 `font-family`（对应 C-03）、`$('sms')` 的 `alert`（对应 C-04）。
