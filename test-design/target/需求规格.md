# 登录模块 · 需求规格（v1.0）

> 本文件是测试用例「预期结果」的唯一依据。凡实现与本文不符，即为缺陷。
> 被测系统：`login-demo.html`（本地单页应用，双击即可运行）

---

## 1. 登录流程

采用两步式：

```
手机号页 ──「下一步」──► 密码页 ──「登录」──► 成功页
```

## 2. 手机号页

| 编号 | 规格 |
|---|---|
| R-1.1 | 输入框仅接受数字，自动过滤空格及其他字符 |
| R-1.2 | 输入长度上限 11 位 |
| R-1.3 | 手机号为空时，「下一步」按钮置灰，不可点击 |
| R-1.4 | 手机号非空时，「下一步」可点击，进入密码页（不在此页做格式拦截） |
| R-1.5 | 页面提供「用短信验证码登录」入口 |

## 3. 密码页

| 编号 | 规格 |
|---|---|
| R-2.1 | 顶部展示当前手机号 |
| R-2.2 | 密码输入框长度 6–20 位 |
| R-2.3 | 密码为空时「登录」按钮保持可点，点击后提示「登录失败，密码不能为空」，不发起校验 |
| R-2.4 | 账号不存在与密码错误，**统一提示「账号或密码错误」**，不得区分 |
| R-2.5 | 页面底部提供《用户协议》勾选框；**未勾选时不允许登录**，点击登录应提示「请先阅读并同意用户协议」 |
| R-2.6 | 登录成功进入成功页；失败停留在当前页并展示提示 |

## 4. 安全要求

| 编号 | 规格 |
|---|---|
| R-3.1 | 同一手机号连续失败 5 次，锁定 60 秒；锁定期间提示「尝试过于频繁，请稍后再试」，且不校验密码 |
| R-3.2 | 登录请求需防止重复提交：点击后按钮进入 loading 或置灰，直到本次请求结束 |

## 5. 测试账号

## 6. 不在本轮范围

- 短信验证码登录的实际校验（入口存在即可）
- 找回密码流程
- 多端登录与互踢
- 服务端接口与数据库（本靶场为纯前端演示）
