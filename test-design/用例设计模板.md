# 测试用例设计模板（可直接套用）

> 用法：复制这份文件 → 改模块名 → 按四维度填表 → 1 小时产出一份能进简历的用例文档。
> 登录模块那份（56 条）就是按这个结构做的，你已经验证过它扛得住面试。

---

## 第一步：先定四个维度（10 分钟）

不要一上来就列「XX 为空」「XX 超长」这种散点。先问自己：**什么因素会影响这个功能的结果？**

| 维度 | 问自己 | 常用方法 |
|---|---|---|
| **输入** | 用户能填/选什么？每个字段的合法与非法范围是什么？ | 等价类 + 边界值 |
| **操作** | 用户会按什么顺序操作？有没有前置依赖？ | 场景法 |
| **状态** | 页面/账号/网络有哪些状态？状态之间怎么迁移？ | 状态迁移 |
| **异常与安全** | 网络断了会怎样？重复提交会怎样？能不能被绕过？ | 错误推测 + 判定表 |

**这四类覆盖不到的地方**，再补一个「兼容与易用」维度（小屏、大字体、深色模式）。

> 为什么这么分：直接列条目容易漏掉状态类和场景类问题，而线上 bug 恰恰高发在这两块。

---

## 第二步：填被测对象（5 分钟）

```
模块名称：
进入路径：
页面元素：
  | 元素 | 说明 | 约束 |
  |---|---|---|
  |      |      |      |
业务规则：
  - 例如：未勾选协议不能提交
  - 例如：同一账号连续输错 5 次锁定
```

**业务规则这一栏最重要**——它决定了哪些是「bug」，哪些是「设计如此」。没有它，用例的预期结果就只能写「按产品定义处理」，那种用例执行时无法判定通过与否。

## 第三步：按维度展开用例（30 分钟）

表格列固定这 6 列，别少：

| 编号 | 用例标题 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| TC-A01 | | | | | P0 |
| TC-A02 | | | | | P1 |

### 编号规则（方便统计和引用）

- `TC-` + 组字母 + 两位序号
- 组字母按维度分：A 输入字段1 / B 输入字段2 / C 操作与提交 / D 场景流程 / E 网络异常 / F 安全 / G 兼容

### 优先级怎么定（别按模块定，按影响定）

| 级别 | 标准 | 例子 |
|---|---|---|
| **P0** | 不通过就没法完成核心操作，或有安全风险 | 正常主流程、防重复提交、登录态残留、密码明文传输 |
| **P1** | 影响体验但能绕过 | 非法字符提示、验证码倒计时、弱网提示 |
| **P2** | 边缘场景 | 粘贴、全角输入、深色模式、横屏 |

⚠️ **反例**：「兼容性测试 = P2」是错的。小屏下按钮被遮挡导致点不到，那是 P0/P1。

### 写预期结果的三个要求

1. **可判定**：能明确说「通过 / 不通过」。写「按产品定义处理」的，执行时只能挂起（Blocked）
2. **写具体文案**：不要写「提示错误」，要写「提示『手机号格式不正确』」
3. **写清「不做什么」**：例如「不发起请求」「按钮保持置灰」——很多 bug 是「多做了」

## 第四步：统计与自检（10 分钟）

```
合计：XX 条
分组：A 14 / B 12 / C 8 / D 8 / E 6 / F 4 / G 4
优先级：P0 XX / P1 XX / P2 XX
```

**自检三条**（每条都要能答「是」）：

- [ ] 条数与分组相加一致（别出现「标题写 52、实际 56」）
- [ ] P0/P1/P2 加起来等于总数（别出现「15+19+18=52 但总数写 56」）
- [ ] 每条预期结果都能判定通过与否，没有「按产品定义处理」

---

## 第五步：面试怎么讲（背这一段）

> 「我先按**影响因素**分组，而不是直接列条目：输入类用等价类加边界值，操作类用场景法，
> 多条件组合用判定表，网络和状态类单独一组。
>
> 因为线上事故里，『网络切换卡死』『退出后登录态没清』这类场景 bug 占比很高，纯等价类覆盖不到。
>
> 按这四类展开，我一共设计了 XX 条，P0 有 XX 条。其中我觉得最有价值的三条是：
> ① 未注册手机号不能提示『账号不存在』——防撞库；② 弱网连点登录——防重复提交；
> ③ 退出登录后杀进程重开——验证登录态清理。」

## 附：缺陷报告六要素（配套用）

写 bug 时缺一不可：

1. **标题**：一句话说清「什么条件下、什么操作、什么现象」
2. **环境**：机型 / 系统版本 / App 版本 / 网络
3. **前置条件**：复现前必须满足什么
4. **复现步骤**：1、2、3，每步一个动作
5. **预期结果**
6. **实际结果**（有截图/录屏/抓包更好）

加分项：**初步定位建议**（怀疑是前端校验缺失还是服务端未做幂等）。
