## 设计思路

没有一上来就列「手机号为空、密码为空」这种散点，而是**先分组再展开**：

```
第一层：什么因素会影响登录结果？
   ├─ 输入数据（手机号、密码）
   ├─ 操作顺序（验证码登录、切换账号、找回密码）
   ├─ 页面状态（网络、多端登录、协议勾选）
   └─ 安全边界（连续失败、异地登录）

第二层：每个因素用哪种方法展开？
   ├─ 输入数据 → 等价类 + 边界值（能穷举）
   ├─ 操作顺序 → 场景法（有前后依赖）
   └─ 组合条件 → 判定表（多条件共同决定结果）
```

这样分的理由：登录的失败点不只是「账号密码错」。实际线上事故里，
「网络切换时登录卡死」「退出登录后 cookie 没清干净」这类**场景类问题**占比很高，
纯等价类覆盖不到。
